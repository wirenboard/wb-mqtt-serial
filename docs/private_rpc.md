# Служебный MQTT-RPC API

> **Внимание:** методы из этого документа служебные. Их используют веб-интерфейс, редактор конфигурации и сервисы поиска и обслуживания устройств Wiren Board, поэтому они **могут меняться без сохранения обратной совместимости**. Для интеграций пользуйтесь методами, описанными в [README](../README.md).

Топик запроса имеет вид `/rpc/v1/wb-mqtt-serial/<Пространство>/<Метод>/<client_id>`, где `client_id` это произвольное имя клиента, посылающего запрос. Ответ публикуется в топик с тем же именем и суффиксом `/reply`. Ответ с ошибкой приходит в том же виде, что и у остальных RPC-запросов драйвера: в поле `error` лежат `code`, короткий `message` и подробное описание в `data`.

## ports/Load

Топик `/rpc/v1/wb-mqtt-serial/ports/Load/client_id`

> **Метод устарел и будет удалён.** Вместо него пользуйтесь методом [ports/List](../README.md#список-портов-и-опрашиваемых-устройств), он отдаёт те же настройки связи портов, а вместе с ними опрашиваемые на портах устройства. У TCP-порта поле с адресом там называется `ip`, а не `address`.

Вернуть список портов, описанных в конфигурации драйвера. Обмена с устройствами не происходит.

### Параметры

Метод не принимает параметров.

### Ответ

JSON-массив, в котором на каждый порт приходится один элемент. Вид элемента зависит от типа порта.

```jsonc
[
   // Последовательный порт
   {
       "path": "/dev/ttyRS485-2",
       "baud_rate": 9600,
       "data_bits": 8,
       "parity": "N",
       "stop_bits": 1
   },

   // Порт Serial over TCP
   {
       "address": "127.0.0.1",
       "port": 2000
   },

   // Порт Modbus TCP
   {
       "address": "192.168.1.10",
       "port": 502,

       // Поле есть только у портов Modbus TCP
       "mode": "modbus-tcp"
   },
   ...
]
```

У последовательного порта передаются все пять полей, даже если в конфигурации заданы не все: значения берутся из настроек порта уже после подстановки значений по умолчанию. Порты, отключённые в конфигурации полем `"enabled": false`, в список не попадают.

## port/Scan

Топик `/rpc/v1/wb-mqtt-serial/port/Scan/client_id`

Найти устройства на шине, используя Быстрый Модбас. Выполнение запроса встраивается в цикл опроса устройств таким образом, что запрос выполнится с высоким приоритетом сразу после окончания текущего цикла опроса.

### Параметры

Для последовательного порта:

```json
{
    // Путь к последовательному порту, на которому будет производиться поиск
    "path": "/dev/ttyRS485-1",

    // Скорость порта
    "baud_rate": 115200,

    // Чётность - N, O или E
    "parity": "N",

    // Количество бит данных
    "data_bits": 8,

    // Количество стоп-бит
    "stop_bits": 2,

    // команда Быстрого Модбаса, которая будет использоваться при поиске
    // актуальная - 70(0x46), устаревшая - 96(0x60)
    // если не задана, то используется 70(0x46)
    "command": 70,

    // режим поиска
    // all - будет произведён поиск всех устройств на шине
    // start - начать поиск до нахождения первого устройства
    // next - искать следующее устройство, если поиск был уже начат, используя режим start
    "mode": "start"
}
```

или для TCP-порта:

```json
{
    // IP адрес или имя хоста шлюза
    "ip": "1.1.1.1",

    // Порт шлюза
    "port": 1234,

    // команда Быстрого Модбаса, которая будет использоваться при поиске
    // актуальная - 70(0x46), устаревшая - 96(0x60)
    // если не задана, то используется 70(0x46)
    "command": 70,

    // режим поиска
    // all - будет произведён поиск всех устройств на шине
    // start - начать поиск до нахождения первого устройства
    // next - искать следующее устройство, если поиск был уже начат, используя режим start
    "mode": "start",

    // При указании значения `modbus` в сокет отправляется Modbus RTU сообщение, что используется при работе через прозрачные шлюзы Modbus RTU-over-TCP.
    // Для работы по Modbus TCP укажите `modbus-tcp`.
    // Необязательный параметр. Если не указан, используется "modbus"
    "protocol": "modbus-tcp"
}
```

### Ответ

```json
{
    // список найденных устройств
    "devices": [
        {
            // серийный номер устройства
            "sn": "13453ghh",

            // название устройства
            "device_signature": "WBMR6C",

            // сигнатура прошивки
            "fw_signature": "mr6cG",

            // если устройство настроено для опроса в wb-mqtt-serial,
            // то в этом параметре передаётся тип устройства из шаблона
            "configured_device_type": "WB-MR6C",

            // список ошибок работы с конкретным устройством
            "errors": [
                {
                    "id": "com.wb.serial_driver.device.read_device_signature_error",
                    "message": "Failed to read device signature."
                },
                {
                    "id": "com.wb.serial_driver.device.read_fw_signature_error",
                    "message": "Failed to read FW signature."
                }
            ],

            // текущие настройки устройства
            "cfg": {
                // адрес
                "slave_id": 100,

                // скорость шины
                "baud_rate": 9600,

                // чётность
                "parity": "N",

                // число бит данных
                "data_bits": 8,

                // число стоп бит
                "stop_bits": 2
            },

            // прошивка устройства
            "fw": {
                // версия
                "version": "1.2.3",
            }
        },
        ...
    ],

    // Ошибка, возникшая в процессе сканирования
    "error": "Serial timeout error"
}
```

Поле `errors` передаётся, только если при чтении регистров устройства была хотя бы одна ошибка. В `message` лежит человекочитаемое описание, оно предназначено для журнала, а не для разбора программой.

|Id|Когда появляется|Что теряется в ответе|
|--|----------------|---------------------|
|`com.wb.serial_driver.device.read_device_signature_error`|не прочитана модель устройства, регистры 200-219, а при неудаче регистры 200-205|нет поля `device_signature`, а `sn` передаётся без поправки, которая нужна устройствам серии MAP|
|`com.wb.serial_driver.device.read_fw_signature_error`|не прочитана сигнатура прошивки, регистр 290|нет поля `fw_signature`|
|`com.wb.serial_driver.device.read_serial_params_error`|не прочитаны параметры связи, регистр 110 скорость, регистр 111 чётность, регистр 112 стоп-биты, либо в регистре чётности оказалось значение, отличное от 0, 1 и 2|в `cfg` нет тех полей, которые не прочитались или не распознались. Запись об ошибке одна на все три регистра, в `message` попадает текст последней неудачи|
|`com.wb.serial_driver.device.read_fw_version_error`|не прочитана версия прошивки, регистр 250|нет поля `fw`|

Поля `cfg.slave_id` и `cfg.data_bits` заполняются всегда, число бит данных при поиске Быстрым Модбасом равно 8.

При возникновении ошибки в процессе сканирования будет возвращён список уже найденных устройств и текст ошибки в поле `error`. Для порта Modbus TCP, который не поддерживает Быстрый Модбас, возвращается пустой список устройств без ошибки.

## config/Load

Топик `/rpc/v1/wb-mqtt-serial/config/Load/client_id`

Вернуть данные, из которых редактор конфигурации строит своё представление настроек драйвера: текущую конфигурацию, схему настроек портов и список типов устройств. Обмена с устройствами не происходит, данные берутся из файла конфигурации и загруженных шаблонов.

### Параметры

```jsonc
{
    // Язык локализованных полей ответа, названий типов устройств
    // и названий групп. Необязательный, по умолчанию "en"
    "lang": "ru"
}
```

### Ответ

```jsonc
{
    // Содержимое /etc/wb-mqtt-serial.conf, преобразованное для редактора
    "config": {},

    // JSON-схема настроек портов
    "schema": {},

    // Типы устройств, сгруппированные для выпадающего списка редактора
    "types": [
        {
            // Название группы, переведённое по "lang"
            "name": "Wiren Board",

            "types": [
                {
                    // Название типа, переведённое по "lang"
                    "name": "WB-MR6C",

                    // Тип устройства (device_type шаблона)
                    "type": "WB-MR6C",

                    // Признак устаревшего шаблона
                    "deprecated": false,

                    // Протокол обмена
                    "protocol": "modbus",

                    // Идентификатор устройства в MQTT
                    "mqtt-id": "wb-mr6c",

                    // Признак шаблона с subdevices
                    "with-subdevices": false,

                    // Поле передаётся только у типов, чей действующий шаблон
                    // загружен из папки пользовательских шаблонов.
                    // У типов со штатными шаблонами поля нет,
                    // его отсутствие трактуется как false
                    "user-defined": true,

                    // Поле передаётся, только если шаблон объявляет "hw"
                    "hw": [
                        {
                            // Сигнатура устройства
                            "signature": "MR6C",

                            // Минимальная версия прошивки, поле необязательное
                            "fw": "1.2.3"
                        }
                    ]
                }
            ]
        }
    ]
}
```

Группы идут в фиксированном порядке: устройства Wiren Board, устаревшие устройства Wiren Board, дальше остальные группы по алфавиту. Типы внутри группы отсортированы по переведённому названию. В группу произвольных устройств (`g-custom`) добавляются поддерживаемые протоколы, у них поле `type` имеет префикс `protocol:`, например `protocol:modbus`.

## config/GetSchema

Топик `/rpc/v1/wb-mqtt-serial/config/GetSchema/client_id`

Вернуть JSON-схему редактора для одного типа устройства или для протокола.

### Параметры

```jsonc
{
    // Тип устройства (device_type шаблона) либо протокол
    // с префиксом "protocol:", например "protocol:modbus". Обязательный
    "type": "WB-MR6C"
}
```

### Ответ

JSON-схема настроек устройства этого типа, построенная по действующему шаблону, либо схема настроек протокола. Схема приходит в поле `result` без обёртки.

## templates/Upload

Топик `/rpc/v1/wb-mqtt-serial/templates/Upload/client_id`

Записать файл шаблона в папку пользовательских шаблонов `/etc/wb-mqtt-serial.conf.d/templates`. Метод появился в версии 2.260.0.

### Параметры

```jsonc
{
    // Полный текст файла шаблона (JSON). Обязательный
    "content": "{ \"device_type\": \"my_device\", ... }",

    // Имя файла для сохранения шаблона. Обязательный.
    // Сервис берёт имя файла без пути, заменяет символы вне [A-Za-z0-9._-]
    // на "_" и добавляет расширение .json, если его нет.
    // Запись за пределы папки пользовательских шаблонов невозможна
    "filename": "my_device.json",

    // Язык локализованных полей ответа, как у config/Load.
    // Необязательный, по умолчанию "en"
    "lang": "ru",

    // Подтверждение перекрытия шаблона типа, используемого устройствами
    // текущей конфигурации. Необязательный, по умолчанию false
    "force": false
}
```

Содержимое шаблона проходит ту же полную проверку, что и при первом использовании шаблона с диска. Шаблоны с `"deprecated": true` загрузить нельзя, при чтении с диска они от этих проверок освобождены, поэтому через RPC не принимаются. Невалидный шаблон отклоняется с ошибкой, файловая система не изменяется.

Для каждого типа устройства хранится не более одного пользовательского файла шаблона: если у типа уже был пользовательский шаблон в файле с другим именем, старый файл удаляется. Если запрошенное имя файла занято шаблоном другого типа, к имени добавляется числовой суффикс (`<имя>-1.json`, `-2` и т.д.), чужие файлы не затираются.

Группа типа в списке устройств определяется действующим шаблоном: пользовательский шаблон, перекрывающий штатный, может объявить другую группу — тип «переезжает» в неё; шаблон без группы попадает в группу «Произвольные устройства» (`g-custom`).

Загрузка и удаление шаблона не влияют на запущенный опрос: он продолжается по прежнему шаблону, изменения применяются штатным сохранением конфигурации в редакторе.

Список типов устройств и схемы редактора конфигураций актуальны уже к моменту ответа. В качестве ответа в топике `/rpc/v1/wb-mqtt-serial/templates/Upload/client_id/reply` будет опубликовано сообщение типа JSON, поле `result` которого содержит поле `types` в том же формате, что и в ответе `config/Load`: массив групп, здесь всегда одна группа с одним типом — описанием действующего (загруженного) шаблона с полем `"user-defined": true` и переведённым (по `lang`) именем группы. Пример:

```jsonc
{
  "types": [
    {
      "name": "Произвольные устройства",
      "types": [
        {
          "name": "Мой контроллер",
          "type": "my_device",
          "deprecated": false,
          "protocol": "modbus",
          "mqtt-id": "my-device",
          "with-subdevices": false,
          "user-defined": true
        }
      ]
    }
  ]
}
```

Если тип загружаемого шаблона используется устройствами текущей конфигурации (`/etc/wb-mqtt-serial.conf`), а `force` не задан, запрос отклоняется, файл не записывается: настройки таких устройств построены по действующему шаблону, и его перекрытие должно быть осознанным. В поле `error.data` ответа передаётся строка `template-in-use` (подробности — тип устройства и количество использующих его устройств — сервис пишет в журнал). Для подтверждения перекрытия нужно повторить запрос с `"force": true`.

Прочие ошибки (запрос не соответствует схеме запроса, некорректный JSON, отсутствует или пуст `device_type`, шаблон не проходит проверку по схеме, ошибка записи файла) возвращают человекочитаемую причину строкой в `error.data`.

## templates/Delete

Топик `/rpc/v1/wb-mqtt-serial/templates/Delete/client_id`

Удалить пользовательский шаблон по типу устройства. Штатные шаблоны из `/usr/share/wb-mqtt-serial/templates` удалить нельзя. Метод появился в версии 2.260.0.

### Параметры

```jsonc
{
    // Тип устройства (device_type), пользовательский шаблон
    // которого нужно удалить. Обязательный
    "type": "my_device",

    // Язык локализованных полей ответа, как у templates/Upload.
    // Необязательный, по умолчанию "en"
    "lang": "ru",

    // Подтверждение удаления шаблона типа, используемого устройствами
    // текущей конфигурации, симметрично templates/Upload.
    // Необязательный, по умолчанию false
    "force": false
}
```

Список типов устройств и схемы редактора конфигураций актуальны уже к моменту ответа. Ответ публикуется в топике `/rpc/v1/wb-mqtt-serial/templates/Delete/client_id/reply`, поле `types` — в том же формате, что у `templates/Upload`:

- если пользовательский шаблон перекрывал штатный, действующим снова становится штатный шаблон — в ответе одна группа с его описанием (уже без поля `"user-defined"`; группа — штатного шаблона, она может отличаться от группы удалённого пользовательского);
- если пользовательский шаблон был единственным для типа, тип исчезает из списка — в ответе пустой массив `"types": []`.

Ошибки: у типа нет пользовательского шаблона (неизвестный тип, только штатный шаблон, повторное удаление) — человекочитаемая причина в `error.data`; тип используется устройствами текущей конфигурации, а `force` не задан — `error.data` содержит `template-in-use` (как у `templates/Upload`), файл не удаляется; ошибка удаления файла — человекочитаемая причина.

## Обновление прошивок устройств Wiren Board

Обмен с устройством встраивается в цикл опроса его порта, опрос других портов продолжается. Одновременно выполняется не больше одного обновления: пока идёт `fw-update/Update` или `fw-update/Restore`, повторные запросы этих методов отклоняются с ошибкой.

### fw-update/Update

Топик `/rpc/v1/wb-mqtt-serial/fw-update/Update/client_id`

Обновить прошивку устройства, его загрузчик или прошивки компонентов.

#### Параметры

```jsonc
{
    // Адрес устройства, целое число от 0 до 255. Обязательный
    "slave_id": 100,

    // Настройки порта. Обязательный
    "port": {
        // Путь к последовательному порту, например "/dev/ttyRS485-1".
        // Для TCP-порта из конфигурации wb-mqtt-serial указывается
        // его описание в виде "адрес:порт", например "192.168.1.10:23".
        // Обязательный
        "path": "/dev/ttyRS485-1",

        // Скорость порта. Необязательный, по умолчанию 9600
        "baud_rate": 9600,

        // Чётность, "N", "O" или "E". Необязательный, по умолчанию "N"
        "parity": "N",

        // Количество бит данных. Необязательный, по умолчанию 8
        "data_bits": 8,

        // Количество стоп-бит. Необязательный, по умолчанию 1
        "stop_bits": 1
    },

    // Протокол обмена с устройством. При значении "modbus" в порт
    // отправляется Modbus RTU сообщение, для работы по Modbus TCP
    // укажите "modbus-tcp". Необязательный, по умолчанию "modbus"
    "protocol": "modbus",

    // Тип обновляемого ПО: "firmware", "bootloader" или "component".
    // Необязательный, по умолчанию "firmware"
    "type": "firmware"
}
```

Настройки порта применяются на время выполнения запроса, после его окончания порт возвращается к настройкам из конфигурации. Значения по умолчанию не берутся из конфигурации порта, поэтому для устройства, которое работает не на 9600 8N1, фактические настройки надо передавать в запросе.

Значение `firmware` обновляет прошивку устройства, а затем прошивки тех компонентов, для которых на сервере есть другая версия. Значение `bootloader` обновляет загрузчик и сразу после этого заливает в устройство актуальную прошивку, потому что после обновления загрузчика устройство остаётся в режиме загрузчика. Значение `component` обновляет только прошивки компонентов.

#### Ответ

Сообщение с результатом `Ok`. Ответ отправляется сразу после чтения информации об устройстве, до начала прошивки, дальше за ходом обновления надо следить по топику состояния. Пока обновление не закончилось, запросы `fw-update/Update` и `fw-update/Restore` возвращают ошибку с кодом `-32000` и сообщением `Task is already executing.`

### fw-update/Restore

Топик `/rpc/v1/wb-mqtt-serial/fw-update/Restore/client_id`

Записать прошивку в устройство, оставшееся в режиме загрузчика, например когда прошивка залилась не полностью. Драйвер читает сигнатуру прошивки, скачивает подходящий файл и прошивает устройство без перезагрузки в загрузчик. Прогресс отражается в топике состояния.

#### Параметры

```jsonc
{
    // Адрес устройства, целое число от 0 до 255. Обязательный
    "slave_id": 100,

    // Настройки порта. Обязательный
    "port": {
        // Путь к последовательному порту, например "/dev/ttyRS485-1".
        // Для TCP-порта из конфигурации wb-mqtt-serial указывается
        // его описание в виде "адрес:порт", например "192.168.1.10:23".
        // Обязательный
        "path": "/dev/ttyRS485-1",

        // Скорость порта. Необязательный, по умолчанию 9600
        "baud_rate": 9600,

        // Чётность, "N", "O" или "E". Необязательный, по умолчанию "N"
        "parity": "N",

        // Количество бит данных. Необязательный, по умолчанию 8
        "data_bits": 8,

        // Количество стоп-бит. Необязательный, по умолчанию 1
        "stop_bits": 1
    },

    // Протокол обмена с устройством. При значении "modbus" в порт
    // отправляется Modbus RTU сообщение, для работы по Modbus TCP
    // укажите "modbus-tcp". Необязательный, по умолчанию "modbus"
    "protocol": "modbus"
}
```

Настройки порта применяются на время выполнения запроса, после его окончания порт возвращается к настройкам из конфигурации. Значения по умолчанию не берутся из конфигурации порта, поэтому для устройства, которое работает не на 9600 8N1, фактические настройки надо передавать в запросе.

#### Ответ

Сообщение с результатом `Ok` до начала прошивки. Если устройство не ответило на чтение сигнатуры, запрос тоже завершается ответом `Ok`, но прошивка не выполняется.

### fw-update/ClearError

Топик `/rpc/v1/wb-mqtt-serial/fw-update/ClearError/client_id`

Удалить запись об ошибке из топика состояния. Без этого запроса запись остаётся там до перезапуска сервиса. Удаляется запись, у которой совпадают `slave_id`, `path` и `type`.

#### Параметры

```jsonc
{
    // Адрес устройства, целое число от 0 до 255. Обязательный
    "slave_id": 100,

    // Порт, к которому подключено устройство. Обязательный
    "port": {
        // Путь к последовательному порту, например "/dev/ttyRS485-1",
        // либо описание TCP-порта в виде "адрес:порт". Обязательный
        "path": "/dev/ttyRS485-1"
    },

    // Тип ПО, при обновлении которого возникла ошибка:
    // "firmware", "bootloader" или "component".
    // Необязательный, по умолчанию "firmware"
    "type": "firmware"
}
```

#### Ответ

Сообщение с результатом `Ok`.

### Топик состояния обновления

Ход обновления публикуется в топик `/wb-mqtt-serial/firmware_update/state` с флагом retain:

```jsonc
{
    // Список устройств, прошивка которых обновляется
    "devices" : [
        {
            // Порт, к которому подключено устройство
            "port": {

                // Путь к последовательному порту, либо описание TCP-порта
                // в формате АДРЕС:ПОРТ
                "path": "/dev/ttyRS485-2"
            },

            // Протокол обмена с устройством, modbus или modbus-tcp
            "protocol": "modbus",

            // Адрес устройства
            "slave_id": 100,

            // Тип обновляемого ПО, firmware, bootloader или component
            "type": "firmware",

            // Процент завершения процесса обновления
            "progress": 50,

            // Текущая версия ПО
            "from_version": "1.0.0",

            // Версия ПО, на которую производится обновление
            "to_version": "2.0.0",

            // Для компонентов номер обновляемого компонента, иначе null
            "component_number": null,

            // Для компонентов модель обновляемого компонента, иначе null
            "component_model": null,

            // Последняя ошибка обновления конкретного устройства, иначе null
            "error": {
                // Идентификатор ошибки
                "id": "com.wb.serial_driver.generic_error",

                // Сообщение об ошибке
                "message": "Internal error. Check logs for more info",

                // Дополнительные данные об ошибке
                "metadata": {
                    "exception": "HTTP 404 downloading https://fw-releases.wirenboard.com/..."
                }
            }
        },
        ...
    ]
}
```

Сообщение публикуется при каждом изменении состояния. После успешного обновления запись удаляется из списка. При ошибке запись остаётся с заполненным полем `error` до запроса `fw-update/ClearError` или перезапуска сервиса. При остановке сервиса топик очищается.

#### Возможные ошибки обновления

|Id|Условия возникновения|поле `metadata`|
|--|---------------------|---------------|
|`com.wb.serial_driver.generic_error`|Ошибка при скачивании файла прошивки или при обмене с устройством во время прошивки|содержит поле `exception` с расширенным описанием ошибки|
